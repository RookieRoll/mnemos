# Proposal

## Why

切换 Claude、Codex、pi 或另一个终端后，现有会话总结能提供部分历史背景，但不能可靠表示尚未结束的任务进度。需要在单机上保存有界的最新检查点，并让新的独立会话在明确工作区范围内读取它，减少重复探索，同时避免同名目录、并行任务和延迟请求造成错误恢复。

## What Changes

- 增加独立于长期知识的会话检查点：每个会话至多一份最新正文，包含 agent 明确记录的进度、下一步、阻塞和引用；不采集完整聊天或工具输出。
- 为新连续性路径建立可靠的本机工作区和会话关联。保留现有 `project` 与历史数据语义，旧记录不按目录名自动绑定或共享。
- 提供显式发布到工作区的共享进度读取；默认保留 owner 范围，不通过共享检查点扩大旧 observation、reflection 或 replay 的可见范围。
- 切换 agent 时创建独立会话，按明确来源或有界候选选择恢复材料；多任务歧义、过旧信息和分支变化必须可见。多个读取者不领取、不消耗进度。
- 检查点更新使用版本校验和精确重试身份，事务提交后才确认保存成功；异常退出最多恢复到最后一次成功写入。
- 将恢复材料接入有预算的 session-start 和显式读取流程，并为 pi 提供会话隔离及旧二进制降级规则。新接口与现有静默 hook 协议分开。
- 增加范围、并发、故障、预算和跨适配器契约测试；通过接续操作数的对照记录评估收益，不预设效率提升比例。

## Capabilities

### New Capabilities

- `session-continuity`: 本机工作区内独立会话之间的检查点保存、显式共享、选择、恢复及生命周期。

### Modified Capabilities

- `memory-context-delivery`: 增加带来源与时效信息的有界恢复材料，不改变现有知识项的排序、警告和注入记录语义。
- `harness-neutral-hooks`: 增加显式选择的连续性接口与提交回执契约，保持旧 hook 输入、输出和退出状态兼容。
- `pi-integration`: 连续性会话启动、共享恢复材料投递、新写工具防护和异步结果隔离。

## Impact

- 预期实现涉及 `internal/session`、一个窄的连续性服务、工作区解析、`internal/storage` 的增量迁移、`internal/prewarm`、CLI/MCP/HTTP 与 `pkg/client` 的薄适配，以及 `pi/extensions` 和已发布 skill 的使用说明。
- SQLite 继续作为事实来源；不新增依赖、LLM 调用、常驻协调服务或第二套知识存储。
- 新状态只覆盖工作区关联和最新检查点。显式清除保留防止旧请求复活所需的最小版本元数据；恢复结果及候选列表不落库。
- 实现时更新协议文档和测试，另行验证实际客户端集成。本变更的规划完成不代表功能已实现、版本已发布或本机插件已更新。

## Non-goals

- 领取、租约、心跳、任务调度、文件锁定及并发编辑冲突解决。
- 跨机器同步、跨工作区自动归并、历史项目身份批量迁移或修改所有旧 memory 的 scope 规则。
- 完整聊天恢复、运行中进程恢复、工具自动重放、会话中后台推送。
- 持久化事件队列、通用 ACK 历史表、检查点版本历史、自动知识晋升和上下文覆盖优先算法改造。
